# TTS エンジンとの約束（P0）

TTS は候補ごとに使い方が違うため、本ツールは次の小さな HTTP の約束だけを前提にします。選んだ TTS エンジンに合わせて、この形の薄い中継サーバーを用意してください（`config/machine.toml` の `[engines.tts]` に起動コマンドと URL を書く）。

## エンドポイント

```
GET  /health   → 200（準備完了）
POST /tts      → 200、本文は audio/wav
```

`POST /tts` の JSON：

| キー | 型 | 内容 |
|---|---|---|
| `text` | 文字列 | 読み上げる文章（本ツールが `tts_chunk_chars` 以下に区切って送る） |
| `reference_audio` | 文字列または null | 参考音声のファイルパス（本ツールの成果物フォルダ内） |
| `reference_text` | 文字列または null | 参考音声で話している内容（分かる場合） |
| `style` | 文字列または null | 話し方の指定 |
| `speed` | 数値 | 1.0 が標準 |
| `seed` | 整数または null | 乱数シード |

## 守ること

- ループバック（127.0.0.1）だけで待ち受ける。
- 1 リクエストずつ処理する（本ツールが推論ロックで順番を守る）。
- 失敗したら 4xx/5xx と理由の文字列を返す。
- 参考音声は本人の同意がある声に限る（画面とツール説明で利用者に確認している）。

## 候補（2026年10月時点、要検証）

日本語に対応し、参考音声で声質を指定できるもの。CosyVoice 系、Qwen3-TTS など。Windows Arm64 か WSL2 で動くか、日本語の読み間違いが少ないかを [prep.md](prep.md) の評価課題で比べて決めます。
